## Required user experience

1. Select the correct lyrics for the current recording and confirm once. Capture an immutable job target (song identity, title/art, stream URL and selected candidates) and let the selection dialog close/minimize immediately.
2. Continue on this laptop in the background while the user navigates, closes the dialog, changes tracks, and listens to any song. If the verified model is cached, use it. Otherwise download/cache/verify it in the background using the existing model machinery, then align. Show honest stage/progress without blocking the music or main UI.
3. A small unobtrusive persistent job-status icon/control remains reachable in the app shell. When ready, show a compact completion popup naming the original song. Clicking it opens that job's result for testing/preview and explicit Save. No forced modal, automatic song switching, automatic publish, or applying song A's words to song B.
4. Improve the poor selection/processing/review UI with Allegra's existing tokens, clear glass and subtle glow, compact icon controls, clear hierarchy, useful states, keyboard/focus handling and reduced-motion behavior. Distinguish Downloading model, Syncing lyrics, Ready to review, Saving, Saved, Failed and Cancelled using plain user-facing copy. No technical worker/cache implementation details in product copy.
5. Preview/testing must target the original recording through existing playback controls. If another song is playing, require the user's explicit preview action before switching; opening a result alone must not interrupt it. Keep explicit Save after testing/review, existing confidence and sign-in requirements, error feedback and local-use behavior. Retain results when the panel closes so they can be reopened.
