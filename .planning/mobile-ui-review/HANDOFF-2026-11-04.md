## How to build and put it on the owner's phone (Samsung M31, adb id RZ8N82QZYXK)

```bash
cd /c/dev/allegra/apps/mobile/android
export EXPO_PUBLIC_BUILD_TIME="$(date -u +%Y-%m-%dT%H:%M:%SZ)" EXPO_PUBLIC_BUILD_COMMIT="$(git rev-parse HEAD)"
./gradlew.bat assembleRelease -PreactNativeArchitectures=arm64-v8a      # run in background, ~10 min warm
adb install -r app/build/outputs/apk/release/app-release.apk            # same debug.keystore as CI: keeps data
adb shell am start -n com.lyricflow.app/.MainActivity
adb logcat -d | grep -iE "UiRecovery|FATAL EXCEPTION|undefined is not"
```

- **Never uninstall.** The installed app is signed with `android/app/debug.keystore` (SHA-256 `fac61745…`), so
  `install -r` upgrades in place.
- The known-good 1.35.3 APK pulled from the phone is in the old session scratchpad (`apk/installed.apk`). If it's
  gone, CI's `apk-latest` is the fallback.
- If a build crashes on start three times, `LaunchGuard` opens `RescueActivity`. "Open LuvLyrics again" is at
  about (540, 1141) on this phone and resets it.
- Don't edit `src/` while Gradle's `createBundleReleaseJsAndAssets` runs: the APK snapshots the files mid-edit.
- In Git Bash, pass `MSYS_NO_PATHCONV=1` to anything that takes `/c` (it gets rewritten to `C:/`).
- **mobile-mcp** was added to Claude Code (local scope): `cmd /c npx -y @mobilenext/mobile-mcp@latest`,
  telemetry off. Its tools load in a new session.
  - Use `mobile_list_elements_on_screen` instead of screenshots, and screen recording to judge smoothness.
  - For frame timings: `adb shell dumpsys gfxinfo com.lyricflow.app framestats`.
